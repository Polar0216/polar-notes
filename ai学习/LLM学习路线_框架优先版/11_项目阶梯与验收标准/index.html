    课程终章：从全局地图到可复现 MiniGPT 项目¶

    本文件是整套教程的课后项目区。前半部分只列题目与提交物，后半部分提供完成方法，不直接混入标准答案。独立参考答案见 12_项目标准答案.md，应在完成自己的第一版后再查看。

    1. 项目题目总览¶

    1.1 Project 1：GPT 全局数据流说明书¶

    使用固定例子“我爱 → 猫”，独立画出训练和生成两条数据流。

    必须包含：

    • Tokenizer、Embedding、Transformer Block、LM Head、Softmax。
    • 每个组件出现前所解决的具体困难，不能只列组件名称。
    • [B,T]、[B,T,C]、[B,T,V] 三个主形状。
    • Attention 与 MLP 的职责。
    • Causal Mask 的作用。
    • 训练分支中的 targets、cross entropy、backward、optimizer。
    • 生成分支中的最后位置 logits、采样、拼接与重复。

    提交物：project01_map.md。正文不少于 800 字，必须使用自己的表述，并标出仍不确定的三处内容。

    1.2 Project 2：MiniGPT 运行与形状审计¶

    运行 code/mini_gpt_complete.py，为一次前向传播建立完整形状表。

    必须完成：

    • 使用 --trace 保存一次输出。
    • 记录 B,T,C,V,H,D 的实际数值。
    • 补充 Q、K、V、scores、weights、context 的形状打印。
    • 验证每个 Block 前后形状相同。
    • 验证 Attention 权重右上角因因果遮罩变为零。
    • 解释位置 Embedding [T,C] 与 token Embedding [B,T,C] 的相加。

    提交物：project02_shapes.md、修改后的代码副本、一次终端输出。

    1.3 Project 3：核心组件单元测试¶

    为 Tokenizer、Causal Self-Attention、MiniGPT 前向传播、保存加载编写最小测试。

    必须测试：

    • Tokenizer 对已知字符满足 decode(encode(text)) == text。
    • Embedding 输入 [B,T] 输出 [B,T,C]。
    • Attention 输入输出均为 [B,T,C]。
    • 因果遮罩下未来位置的注意力概率为零。
    • MiniGPT logits 为 [B,T,V]，loss 为标量且有限。
    • eval() 模式下保存加载前后的 logits 在容差内一致。
    • 学习率为零时，一次 optimizer.step() 不改变参数。

    提交物：test_mini_gpt.py 和测试运行结果。

    1.4 Project 4：从零重建 MiniGPT¶

    不复制完整文件，依据数据流自行建立一个单文件字符级 GPT。

    程序必须包含：

    • 可保存恢复的字符级 Tokenizer。
    • 输入目标错开一位的 Batch 采样。
    • Token Embedding 与 Position Embedding。
    • 多头 Causal Self-Attention。
    • Pre-Norm、Residual 与 MLP。
    • LM Head 和序列交叉熵。
    • AdamW 训练循环、验证、梯度裁剪。
    • 最佳验证损失 Checkpoint。
    • 温度和 Top-k 生成。
    • 一次 shape trace。

    提交物：my_mini_gpt.py、README.md、训练日志、Checkpoint 和一份故障记录。

    1.5 Project 5：受控预训练对照实验¶

    使用相同语料、随机种子、训练 token 预算和评估方式，只比较一个模型变量。

    从以下变量中任选一个：

    • n_layer = 1 与 n_layer = 3；
    • n_embd = 48 与 n_embd = 96；
    • block_size = 32 与 block_size = 64；
    • Dropout 为 0 与 0.1。

    报告必须包含：参数量、运行设备、训练时间、训练和验证损失、固定 Prompt 生成样例、曲线或表格、观察、解释、局限与下一步。

    提交物：project05_experiment.md、原始日志和配置。

    1.6 Project 6：生成策略与性能实验¶

    对同一个 Checkpoint 和同一组 Prompt，比较：

    贪心生成
temperature = 0.6, top_k = 10
temperature = 1.0, top_k = 20
temperature = 1.2, top_k = 40

    每种配置至少运行五次，记录重复程度、可读性、输出差异、生成 token 数和耗时。说明随机采样为何需要多次运行。

    提交物：project06_inference.md 和可重复运行脚本。

    1.7 Project 7：LLM 应用方案设计¶

    从以下任务中任选一个：

    • 私有课程资料问答；
    • 数学题步骤讲解；
    • 本地文件整理助手；
    • 带工具调用的实验记录助手。

    设计中必须明确：

    • 基础模型的职责；
    • Prompt、RAG、LoRA、Tool Calling、Memory、Agent 中真正需要的组件；
    • 数据来源与权限；
    • 输入输出 schema；
    • 离线评估集；
    • 错误处理、停止条件与人工确认；
    • 延迟、成本、隐私和安全约束。

    提交物：project07_system_design.md，只要求设计与最小原型，不要求训练大模型。

    2. 通用完成方法¶

    所有项目按相同过程推进：

    把题目翻译为可检查的输入与输出
→ 列出最小子任务
→ 先做能够运行的最小版本
→ 增加 shape 与断言
→ 构造极小可人工检查的数据
→ 记录第一次失败
→ 每次只修改一个问题
→ 完成验收表
→ 最后撰写结论

    开始写代码前先写四行：

    输入：
输出：
必须保持的形状：
判断成功的证据：

    这四行能把“看懂但不知道如何下手”变成具体接口。

    3. Project 1 完成指导¶

    先在纸上或 Markdown 中放置七个框：

    文本 → ids → vectors → contextual vectors → logits → probabilities → token

    再把组件名称分别写到箭头上，最后增加训练分支。每个框只回答三件事：

    里面的数据是什么
shape 是什么
是谁把它变成下一种数据

    不要先写公式。图完成后再为 Linear、Softmax 和 cross entropy 补充一条公式。

    4. Project 2 完成指导¶

    复制代码到独立项目目录，不直接修改课程标准文件：

    projects/project02/
├── mini_gpt_trace.py
├── trace_output.txt
└── project02_shapes.md

    在 Attention 中逐步打印：

    print("query before heads", query.shape)
print("query after heads", query.shape)
print("scores", scores.shape)
print("weights", weights.shape)
print("context before merge", context.shape)
print("context after merge", context.shape)

    只用 B=1,T=4 打印具体注意力矩阵。大张量只打印 shape、最小值、最大值和是否有限。

    5. Project 3 完成指导¶

    每个测试遵循 Arrange、Act、Assert：

    def test_embedding_shape():
    # Arrange
    B, T, C, V = 2, 3, 8, 11
    idx = torch.randint(0, V, (B, T))
    embedding = torch.nn.Embedding(V, C)

    # Act
    output = embedding(idx)

    # Assert
    assert output.shape == (B, T, C)

    先直接使用 python test_mini_gpt.py 和普通 assert，掌握后再引入 pytest。

    未来权重测试需要让 Attention 暴露或暂时返回 weights。完成测试后恢复正式接口，或增加只在调试时启用的可选返回值。

    6. Project 4 完成指导¶

    按以下顺序构建，每一步运行后再继续：

    1. Tokenizer encode/decode 往返成功。
    2. get_batch() 能产生错开一位的 [B,T]。
    3. 只有 Embedding 和 LM Head 的模型能产生 [B,T,V]。
    4. 单头 Attention 通过形状与因果测试。
    5. 扩展为多头并恢复 [B,T,C]。
    6. 加入 MLP、LayerNorm 和 Residual 构成一个 Block。
    7. 用 ModuleList 堆叠多个 Block。
    8. 接入交叉熵并完成单批过拟合。
    9. 接入训练、验证和最佳 Checkpoint。
    10. 最后增加自回归生成。

    每完成一步进行一次小提交，避免所有组件一次写完后无法定位错误。

    7. Project 5 完成指导¶

    先创建配置表：

    配置 实验 A 实验 B
    唯一变量 1 3
    seed 42 42
    训练 token 数 相同 相同
    语料版本 相同 相同
    其他超参数 相同 相同

    曲线横轴优先使用 step 或 tokens seen，纵轴使用 train/validation loss。不要只比较各自“最漂亮的一次”生成。

    8. Project 6 完成指导¶

    把生成与训练分开，确保每种采样参数使用同一个模型。为每次运行记录：

    模型 Checkpoint 哈希或路径
Prompt
seed
temperature
top_k
生成文本
token 数
耗时

    分析时不要仅写“更好看”。定义简单标准，例如明显重复字符比例、是否包含 <unk>、人工可读评分和五次输出的不同率。

    9. Project 7 完成指导¶

    先写不使用 Agent 的最小基线。例如资料问答的基线可以只是“检索一次 → 拼接证据 → 生成一次”。只有当任务确实需要多步决策和工具反馈时，才增加 Agent 循环。

    架构图至少包含：

    输入
→ 校验
→ 检索或工具
→ 上下文构造
→ 模型
→ 结果验证
→ 输出或人工确认

    每个外部动作标记读取或写入、权限范围、超时、重试与审计方式。

    11. 课程最终验收¶

    完成 Project 1 至 4 后，应能解释和实现基础 GPT。完成 Project 5 与 6 后，应能进行可复现训练与推理实验。Project 7 用于确认你能把模型放回真实系统，而不是把所有需求都错误地归结为训练更大模型。

    最终口头复述应覆盖：

    文本如何变成 token
token 如何变成上下文表示
Attention 与 MLP 如何分工
logits 如何变成损失或下一个 token
梯度如何更新参数
训练、验证和生成如何区分
Checkpoint 如何保证可恢复
推理系统为何需要 KV Cache
微调、RAG 与 Agent 分别解决什么问题
