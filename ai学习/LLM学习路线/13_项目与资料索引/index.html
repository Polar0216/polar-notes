    项目与学习资料索引¶

    链接核对日期：2026-07-01。GitHub 项目和 SDK 更新很快，安装命令、模型支持和 API 以项目当前 README/官方文档为准。先固定依赖版本，再做实验。

    1. 怎么使用这个索引¶

    每个主题按三种材料学习：

    1. 教材/教程：第一次建立心智模型。
    2. Mini 源码：能一两天读完并复刻核心。
    3. 工业项目：理解工程取舍，只沿一条数据流阅读。

    不要同时 clone 十几个仓库。完成当前模块的验收项目后，再读对应源码。

    2. 计算机、Python、Git 和数学¶

    • Python 官方中文教程：语法的权威查阅；按模块 1 所需内容读，不必一次看完。
    • Pro Git 中文版：先读起步、Git 基础和分支。
    • NumPy Quickstart：重点是 shape、axis、broadcasting 和向量化。
    • Dive into Deep Learning 中文版：系统教材；优先预备知识、线性网络、MLP、计算和 NLP/Attention 相关章节。
    • 3Blue1Brown 线性代数本质：用于直觉；仍需配合手算和 NumPy 练习。
    • Calculus / Neural Networks 可视化专题：用图像理解梯度与反向传播。

    3. 自动微分与 PyTorch¶

    • PyTorch Tutorials：依次学 tensors、autograd、neural networks 和 data tutorials。
    • karpathy/micrograd：比 tinygrad 更适合作为自动微分第一份源码，先复刻标量计算图。
    • tinygrad/tinygrad：学习 Tensor、autograd、调度/编译的紧凑实现；不是模块 2 第一天就通读的项目。
    • d2l-ai/d2l-zh：把数学、PyTorch 与完整训练实验连接起来。

    4. Tokenizer、Transformer 与 GPT¶

    • Hugging Face NLP Course：Tokenizer：理解训练和使用 tokenizer 的工程细节。
    • google/sentencepiece：SentencePiece 的官方实现；先理解思想，再看 CLI/API。
    • Hugging Face tokenizers：高性能 tokenizer 工程实现。
    • The Annotated Transformer：逐段解释原始 Transformer；它是 encoder-decoder 架构，和 decoder-only GPT 有差异。
    • karpathy/minGPT：极简 GPT，适合第一次源码阅读。
    • karpathy/nanoGPT：训练中型 GPT 的紧凑项目；先跑字符 Shakespeare 配置。
    • karpathy/build-nanogpt：按提交历史一步步构建 GPT-2，适合完成 MiniGPT 后对照。
    • rasbt/LLMs-from-scratch：从数据、Attention、GPT、预训练到微调的完整配套源码，适合做主教材。

    推荐源码阅读顺序：自己的实现 → micrograd（自动微分）→ minGPT → LLMs-from-scratch 对应章节 → nanoGPT → tinygrad。

    5. 推理与部署¶

    • ggml-org/llama.cpp：本地推理、量化与跨硬件优化。
    • vllm-project/vllm：高吞吐服务、调度与 KV cache 管理。
    • sgl-project/sglang：高性能 LLM/VLM serving 和结构化工作流。

    这些是工业项目。先做模块 5 的采样器和 KV Cache，再读它们的架构文档、benchmark 和 cache/scheduler 入口。

    6. 微调¶

    • Hugging Face PEFT：LoRA 等参数高效微调的核心库与文档。
    • hiyouga/LLaMA-Factory：覆盖多模型和多种训练方法；适合跑通标准流程、比较配置。
    • unslothai/unsloth：关注低显存和训练性能优化；硬件与支持矩阵看当前文档。

    先手算 LoRA 参数量、检查模板和标签 mask，再用框架。不要用框架 UI 替代对数据的理解。

    7. RAG¶

    • langchain-ai/rag-from-scratch：从 RAG 基本部件出发的教程材料。
    • NirDiamant/RAG_Techniques：高级技巧 notebook 集合；注意检查仓库当前许可证，它并非所有场景都可随意商用。
    • microsoft/graphrag：图结构 RAG 方法与实现；官方仓库明确提醒索引可能昂贵，应从小数据开始。
    • FAISS：向量相似度搜索基础库。
    • Qdrant：带过滤和服务能力的向量数据库案例。

    学习顺序：NumPy 暴力 cosine → FAISS/向量库 → hybrid/rerank → GraphRAG。LangChain 是编排工具，不是理解 RAG 的前置条件。

    8. Memory¶

    • mem0ai/mem0：以通用 Agent memory layer 为目标。
    • getzep/zep：关注对话/Agent 记忆和时间关系；查看当前产品与开源仓库边界。
    • letta-ai/letta：原 MemGPT，关注有状态 Agent 与上下文/记忆管理。
    • Generative Agents 论文：importance、recency、relevance 和 reflection 的经典来源；实现时仍需自己验证。

    用同一套跨会话测试比较三项目，不要按功能列表判断优劣。

    9. Agent、浏览器与代码¶

    • langchain-ai/langgraph：状态图、持久化与可恢复 Agent 编排。
    • browser-use/browser-use：浏览器 Agent；务必在测试站点和受限权限下学习。
    • OpenHands/OpenHands：完整代码 Agent 应用，适合研究事件流、sandbox 和仓库交互。
    • FoundationAgents/OpenManus：通用 Agent 框架案例；先做安全评估再运行外部工具。
    • OpenInterpreter/open-interpreter：自然语言调用本地代码/系统；其文档也提醒代码执行风险，应使用隔离环境。
    • continuedev/continue：IDE/代码 Agent 方向。
    • Aider-AI/aider：终端中的代码协作与 Git 工作流。
    • cline/cline：IDE Agent 与工具审批交互案例。

    先读一个项目的一条轨迹：用户输入→状态→模型→工具→sandbox→事件→UI，不要横向通读所有文件。

    10. Multi-Agent¶

    • microsoft/autogen：事件驱动与多 Agent 应用框架。
    • crewAIInc/crewAI：角色/任务式多 Agent 编排。
    • camel-ai/camel：多 Agent 研究与框架。

    接口和产品定位会演进。比较时固定同一任务、模型、工具和预算，并保留单 Agent 基线。

    11. MCP¶

    • MCP 官方文档：先读架构、server/client 与安全。
    • MCP 规范: 遇到生命周期、能力协商、transport 或 schema 问题时查权威定义。
    • modelcontextprotocol/python-sdk：官方 Python SDK。2026-07-01 正处于 v1 稳定与 v2 预发布过渡期；务必锁定主版本并阅读对应分支文档。
    • modelcontextprotocol/typescript-sdk：官方 TypeScript SDK。

    12. 多模态与机器人¶

    • QwenLM GitHub Organization：从当前模型仓库找到 Qwen-VL/Qwen 系列官方代码和模型说明。
    • Hugging Face Transformers：查看目标 VLM 的 processor/model 文档与示例。
    • ROS 2 Documentation：Node、Topic、Service、Action、TF2 和 bag；选择与你安装发行版一致的文档。
    • MoveIt Documentation：运动规划、碰撞场景和机械臂教程。
    • Gazebo Documentation：先在仿真中验证。

    13. 一手论文建议¶

    不要以“读完所有论文”为目标。每篇回答：解决什么、核心公式/结构、实验如何证明、限制是什么、能否做一个 Mini 复现。

    14. GitHub 项目的固定阅读模板¶

    # 项目阅读：xxx

## 它解决什么问题
输入、输出、目标用户、非目标。

## 最小运行
版本、硬件、命令、样例、耗时。

## 模块图
入口、状态、模型、工具、存储、输出。

## 一条数据流
从一个真实请求跟到最终响应，记录函数和形状。

## 3～5 个核心文件
为什么核心，而不是简单列文件名。

## 关键取舍
准确性/速度/成本/复杂度/安全。

## Mini 复刻
只保留核心思想，不复制框架外壳。

## 我发现的限制
失败样例、许可证、部署或安全限制。
