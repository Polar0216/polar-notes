    从计算机新手到 LLM Engineer：可执行学习路线¶

    这套资料是对上级目录中 AI_项目推荐.md 的补全和重排。原路线给出了正确的项目方向，但默认学习者已经会 Python、命令行、Git、线性代数和基本的软件调试。本教程把这些被省略的台阶补回来，并为每一阶段提供可验收的成果。

    核心原则：不要用“看完了多少视频”衡量进度，要用“能否不看答案完成一个小项目并解释它”衡量进度。

    1. 最终会获得什么能力¶

    完成主线后，你应当能够：

    1. 用 Python、NumPy 和 PyTorch 实现并训练神经网络。
    2. 从零解释并实现 Tokenizer、Attention 和一个小型 GPT。
    3. 理解预训练、推理、LoRA/QLoRA 的数据流和显存开销。
    4. 独立构建、评估并改进一个 RAG 系统。
    5. 构建带工具、记忆、规划和安全边界的 Agent。
    6. 用 MCP 接入外部能力，把各模块整合为 Second Brain OS。
    7. 读懂主流 GitHub 项目的结构，而不只是复制命令运行。

    “完成”不等于训练出能和商业模型竞争的大模型。个人算力最适合学习原理、训练很小的模型、微调开源模型，以及搭建完整系统。

    2. 推荐顺序¶

    阶段 教材 建议产物 零基础参考用时
    0 环境与学习方法 可复现的 Python 项目模板 1～2 周
    1 Python、Git 与数学基础 + 数学手算 文本统计器、矩阵练习、Git 仓库 4～8 周
    2 NumPy 神经网络与 PyTorch NumPy MLP、PyTorch MNIST 4～6 周
    3 Tokenizer、Attention、Transformer + Attention 手算 BPE、注意力热力图、Transformer Block 4～7 周
    4 MiniGPT 与预训练 可生成文本的小 GPT 3～6 周
    5 推理、量化与部署 采样器、KV Cache 对照实验、本地 API 3～5 周
    6 微调：SFT、LoRA、QLoRA 数学老师模型与评估报告 3～5 周
    7 RAG：从检索到 GraphRAG 带引用的个人知识库 4～7 周
    8 Tool Calling 与 Code Interpreter 安全的计算器/Python 工具 Agent 2～4 周
    9 Memory 短期、摘要、向量和画像记忆 3～5 周
    10 Agent 与 Multi-Agent 可恢复、可观测的任务 Agent 4～7 周
    11 MCP、AI OS 与工程化 Second Brain OS 6～12 周
    12 多模态与机器人 图像问答或仿真机械臂 Demo 选修，6 周起

    总用时取决于已有基础和每周投入。零基础、每周 8～12 小时，主线通常需要 9～15 个月；原路线中“2～3 周学完 Python + 深度学习”只适合已有编程和数学基础的人。

    原理推导与手算讲义¶

    主模块负责完整路线与项目，下面的补充讲义专门把容易被代码遮住的原理拆开：

    讲义 重点
    数学直觉与手算 导数、梯度、链式法则、矩阵乘法、概率与对数
    NumPy/PyTorch 主章 单神经元到矩阵反向传播、Softmax、交叉熵和自动微分
    Attention 与 Transformer 手算 Q/K/V、缩放、Mask、多头、LayerNorm 和残差
    训练原理与显存估算 自回归损失、参数量、AdamW、激活与显存账本
    采样、KV Cache 与量化 Temperature、Top-k/Top-p、Cache 大小和量化误差
    LoRA 与 QLoRA 推导 低秩参数量、缩放、合并、NF4 与显存
    RAG 检索与评估手算 Cosine、BM25、RRF、Recall、MRR 与 nDCG
    Tool 到 Agent 完整案例 权限、状态、注入防护、幂等与崩溃恢复
    Second Brain 工程蓝图 数据模型、请求生命周期、策略、测试与发布

    Markdown 与 LaTeX 约定¶

    全套资料使用兼容常见 Markdown 数学渲染器的写法：

    • 行内数学使用单美元符号，例如 $y=Wx+b$；
    • 独立公式使用两个美元符号，并在公式块前后保留空行；
    • 程序变量、路径和命令仍使用行内代码格式；
    • 多行矩阵使用标准 LaTeX 的 $\begin{bmatrix}\cdots\end{bmatrix}$；
    • 不再使用当前预览器无法正确识别的反斜杠方括号公式分隔符。

    统一文档使用标准¶

    为了避免“例子、讲解、作业和答案混在一起”，主模块统一按以下顺序组织：

    1. 目标：本模块学完后能做什么。
    2. 学习导航：正文、补充讲义、验收与 Project 的正确学习顺序。
    3. 原理讲解与文内例子：例子紧跟概念，用于理解，不当作课后作业单独罗列。
    4. 验收与复盘：先检查自己是否能解释、修改和测试。
    5. 课后 Project：始终位于文末；先独立完成，再查看单独的标准答案或参考实现。

    带 A 的文件是补充讲义，统一采用“讲义定位与使用方式 → 推导/手算 → 自测或检查表”的结构。它们服务于对应主模块，不额外插入重复 Project。

    标准答案文件只提供完整代码、完整推导和对照说明；学习时应先做 Project，再打开答案文件。这样能把“看懂”变成“能独立下手”。

    3. 三条可选路径¶

    路径 A：原理优先（推荐）¶

    严格按 0→11 学。优点是后期排错能力强，缺点是前两个月产品感较弱。

    路径 B：作品优先¶

    先完成 0、1 的 Python 核心，然后用现成 API 做一个最小 RAG；有成就感后回到 2～6 补原理。注意：不能永远停在框架调用层。

    路径 C：机械/机器人方向¶

    完成 0～3、5、8、10、11 后进入 12；预训练和高级 RAG 可以稍后补。机器人项目的安全边界、仿真和坐标变换比“让 LLM 直接控制电机”更重要。

    4. 每周节奏¶

    一次 90～120 分钟的学习单元可这样安排：

    • 20 分钟：读概念，手写自己的理解。
    • 45 分钟：关闭教程，自己实现。
    • 20 分钟：测试、画图、制造错误并修复。
    • 15 分钟：记录“输入→形状→输出”和本次踩坑。

    每周至少保留一个完整时段做项目整合。建议时间比例：代码 50%，概念 25%，调试 15%，复盘 10%。

    5. 每阶段的通用验收¶

    只有同时满足下面四项，才算学会：

    1. 运行：在干净环境中按照 README 能重新运行。
    2. 解释：能用自己的话解释数据从哪里来、经过什么形状变化、输出为何合理。
    3. 修改：能改一个关键参数并预测结果方向。
    4. 测试：至少有正常、边界和错误输入三类测试。

    每个项目都建议保存：README.md、requirements.txt 或 pyproject.toml、src/、tests/、实验配置、结果图以及复盘笔记。

    6. 硬件策略¶

    • 只有 CPU：可完成 Python、NumPy、小型网络、字符级 GPT、RAG、Agent、MCP；训练要缩小数据和模型。
    • 8GB 左右显存：可训练小 GPT，对 0.5B～3B 级模型做谨慎的量化推理或小规模 QLoRA，具体取决于序列长度和实现。
    • 12～24GB 显存：微调和本地推理选择更多，但仍应先估算显存。
    • 没有 NVIDIA GPU：不要卡住，可用 CPU、小数据、云端按时租卡。学习目标是验证原理，不是烧钱比参数。

    不要一开始下载几十 GB 的模型。先用最小模型打通流程，再替换模型。

    7. 贯穿全程的实验记录模板¶

    # 实验：名称

## 问题
我想验证什么？

## 假设
改变哪个变量，指标应怎样变化？为什么？

## 环境
Python / PyTorch / GPU / 依赖版本 / 随机种子

## 数据
来源、许可、样本数、切分方法、清洗方法

## 配置
模型大小、学习率、batch、上下文长度等

## 结果
训练/验证指标、速度、显存、样例和失败案例

## 结论
假设是否成立？下一次只改什么？

    8. 先记住的五个警告¶

    1. GitHub README 的安装命令会随版本变化；优先看项目当前文档，不要盲抄旧博客。
    2. 不可信 PDF、网页和用户输入都可能包含提示注入；它们是数据，不是系统指令。
    3. 给 Agent Shell、浏览器、邮箱或文件权限前，必须做最小权限、确认和审计。
    4. 训练数据必须检查版权、隐私、许可证和敏感信息。
    5. Demo 能回答一个问题不代表系统有效；必须建立评估集和失败案例库。
