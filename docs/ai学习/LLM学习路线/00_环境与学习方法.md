## 1. 计算机到底在执行什么

程序是按规则处理数据的指令集合。源代码是人类较容易读的文本；Python 解释器读取它并执行。操作系统负责文件、进程、内存和设备；终端只是你用文字向操作系统发送命令的界面。

几个常被混淆的词：

- **文件**：持久化的数据，例如 `train.py`、`data.jsonl`。
- **目录**：组织文件的容器。
- **进程**：正在运行的程序。关闭终端不一定等于正确保存了进程状态。
- **内存（RAM）**：CPU 使用的临时工作区；断电会消失。
- **显存（VRAM）**：GPU 的工作区。参数、梯度、优化器状态和激活值都会占显存。
- **路径**：文件地址。绝对路径从盘符/根目录开始，相对路径从当前工作目录开始。

当错误写着 `FileNotFoundError`，先不要怀疑模型：打印当前目录，检查相对路径相对于谁。

```python
from pathlib import Path

print(Path.cwd())
print(Path("data/train.txt").resolve())
```

## 2. PowerShell 最小命令集

```powershell
# 当前目录和文件
Get-Location
Get-ChildItem

# 进入目录、返回上级
Set-Location .\my_project
Set-Location ..

# 创建目录
New-Item -ItemType Directory -Path .\data

# 查看 Python 和 Git
python --version
git --version
```

路径含空格时要加引号。不要以管理员身份运行来“解决所有问题”；那通常只是掩盖路径或权限设计错误。

## 3. Python 环境为什么要隔离

项目 A 可能依赖某个版本的 PyTorch，项目 B 依赖另一版本。如果全装到同一处，升级一个项目会破坏另一个。虚拟环境相当于为项目准备独立工具箱。

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install numpy pytest
```

这几行是在 **Windows PowerShell 里创建并启用 Python 虚拟环境，然后安装依赖**：

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install numpy pytest
```

逐句解释：

`python -m venv .venv`
创建一个叫 `.venv` 的虚拟环境文件夹。以后这个项目用自己的 Python 包，不污染系统 Python。

`.\.venv\Scripts\Activate.ps1`
激活虚拟环境。成功后命令行前面通常会出现：

```powershell
(.venv) PS ...
```

`python -m pip install --upgrade pip`
把这个虚拟环境里的 `pip` 更新到最新版。

`python -m pip install numpy pytest`
安装两个包：

- `numpy`：科学计算、矩阵、数组运算
- `pytest`：Python 测试框架，用来运行测试代码

如果第二行报错类似：

```powershell
running scripts is disabled on this system
```

可以在 PowerShell 里执行：

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

然后重新激活：

```powershell
.\.venv\Scripts\Activate.ps1
```

如果只是临时绕过，也可以用：

```powershell
.\.venv\Scripts\python.exe -m pip install numpy pytest
```

这样不激活虚拟环境也能直接往 `.venv` 里装包。

`-m` 的意思是：**把后面的东西当成 Python 模块来运行**。

比如：

```powershell
python -m venv .venv
```

可以拆成：

```
python        调用 Python
-m            以“模块”的方式运行
venv          要运行的模块名
.venv         给 venv 的参数：创建一个叫 .venv 的虚拟环境文件夹
```

所以这句不是说运行一个叫 `venv.py` 的文件，而是说：

> 让 Python 去运行内置模块 `venv`，然后在当前目录创建一个 `.venv` 虚拟环境。

类似的还有：

```powershell
python -m pip install numpy
```

意思是：

> 让 Python 运行 `pip` 模块，然后执行 `install numpy`。

这样写比直接写 `pip install numpy` 更稳，因为它能确保用的是当前这个 Python 对应的 pip。

---

第二行：

```powershell
.\.venv\Scripts\Activate.ps1
```

对，它就是一个**文件路径**，指向虚拟环境里的激活脚本。

拆开看：

```
.\              当前文件夹
.venv\          虚拟环境文件夹
Scripts\        Windows 下虚拟环境存脚本的文件夹
Activate.ps1    PowerShell 用的激活脚本
```

所以这句的意思是：

> 运行当前目录下 `.venv\Scripts\Activate.ps1` 这个脚本，激活虚拟环境。

其中最前面的：

```powershell
.\
```

表示“从当前目录开始找”。

如果你的项目目录是：

```
D:\my_project
```

那这句实际指向的就是：

```
D:\my_project\.venv\Scripts\Activate.ps1
```

激活成功后，PowerShell 前面一般会出现：

```powershell
(.venv) PS D:\my_project>
```

这个 `(.venv)` 就说明你现在进入了虚拟环境。

若 PowerShell 拒绝执行激活脚本，可以先理解并按组织安全策略调整执行策略；也可以不激活，直接调用 `.\.venv\Scripts\python.exe`。验证当前解释器：

```powershell
python -c "import sys; print(sys.executable)"
python -m pip --version
```

推荐写 `python -m pip` 而不是裸 `pip`，这样更明确地使用当前 Python 对应的 pip。

### 依赖文件

小项目可用：

```powershell
python -m pip freeze > requirements.txt
python -m pip install -r requirements.txt
```

但 `freeze` 会记录所有间接依赖。长期项目更适合 `pyproject.toml` 和锁文件工具。入门阶段先掌握虚拟环境和 `requirements.txt`，不要同时折腾五种包管理器。

## 4. GPU、CUDA 和 PyTorch 的关系

- GPU 是硬件。
- 驱动让操作系统与 GPU 通信。
- CUDA 是 NVIDIA 的并行计算平台。
- PyTorch 是上层张量/深度学习库，并提供对应 CUDA 构建。

安装 PyTorch 时应使用其官网针对系统和硬件生成的命令，不要从旧文章复制版本。安装后用下面代码检查：

```python
import torch

print("torch:", torch.__version__)
print("CUDA available:", torch.cuda.is_available())
if torch.cuda.is_available():
    print(torch.cuda.get_device_name(0))
```

这段代码是在**检查 PyTorch 是否安装成功，以及你的电脑能不能用 CUDA 显卡加速**。

```python
import torch

print("torch:", torch.__version__)
print("CUDA available:", torch.cuda.is_available())
if torch.cuda.is_available():
    print(torch.cuda.get_device_name(0))
```

逐句看：

```python
import torch
```

导入 PyTorch 库。`torch` 是 PyTorch 的主要模块。

```python
print("torch:", torch.__version__)
```

输出当前安装的 PyTorch 版本，比如可能是：

```
torch: 2.5.1+cu121
```

其中：

- `2.5.1` 是 PyTorch 版本
- `+cu121` 表示这个版本带 CUDA 12.1 支持
- 如果是 `+cpu`，说明你装的是 CPU 版本，不能用 NVIDIA 显卡加速

```python
print("CUDA available:", torch.cuda.is_available())
```

检查 PyTorch 是否能调用 CUDA。

CUDA 是 NVIDIA 显卡用来做并行计算的工具。深度学习里，如果 CUDA 可用，模型训练和推理通常会快很多。

输出可能是：

```
CUDA available: True
```

或者：

```
CUDA available: False
```

如果是 `True`，说明 PyTorch 可以用你的 NVIDIA 显卡。

如果是 `False`，常见原因是：

1. 电脑没有 NVIDIA 显卡；
2. 装的是 CPU 版 PyTorch；
3. 显卡驱动没装好；
4. CUDA/PyTorch 版本不匹配；
5. 当前虚拟环境里装的 torch 不对。

最后这段：

```python
if torch.cuda.is_available():
    print(torch.cuda.get_device_name(0))
```

意思是：

> 如果 CUDA 可用，就输出第 0 块显卡的名字。

比如：

```
NVIDIA GeForce RTX 4060 Laptop GPU
```

这里的 `0` 是显卡编号。大多数笔记本只有一块独显，所以编号就是 `0`。

整体来说，这段代码就是一个 **PyTorch + CUDA 检查脚本**。如果你运行后看到类似：

```
torch: 2.x.x+cu...
CUDA available: True
NVIDIA GeForce RTX ...
```

那就说明你的 PyTorch GPU 环境基本正常。

`nvidia-smi` 能看到 GPU，不代表当前 PyTorch 一定支持 CUDA；反过来，代码也必须把模型和张量放到同一设备。

```python
device = torch.device("cuda" if torch.cuda.is_available() else "cpu")
model = model.to(device)
x = x.to(device)
```

## 5. IDE、脚本和 Notebook

- `.py` 脚本适合可复现的程序、测试和正式项目。
- Jupyter Notebook 适合逐步实验和画图，但执行顺序可能混乱。
- VS Code/PyCharm 是编辑器/IDE，不是 Python 本身。

Notebook 里“上面改了，下面还用旧变量”是常见幽灵错误。提交结果前重启内核并从头运行一次。

## 6. 错误信息怎么读

Python Traceback 从“调用链”展开，通常先看最后一行的异常类型和消息，再向上找第一处属于自己项目的代码。

常见类型：

| 错误                          | 常见原因              | 第一检查项                  |
| ----------------------------- | --------------------- | --------------------------- |
| `SyntaxError`                 | 语法错误              | 报错行及上一行括号/引号     |
| `NameError`                   | 变量未定义            | 拼写、作用域、执行顺序      |
| `ModuleNotFoundError`         | 环境不对或未安装      | `sys.executable` 与 pip     |
| `FileNotFoundError`           | 路径不对              | `Path.cwd()` 和绝对路径     |
| `TypeError`                   | 对象类型/函数参数不符 | `type(x)` 与函数签名        |
| `RuntimeError: size mismatch` | 张量形状不匹配        | 每一步 `.shape`             |
| CUDA OOM                      | 显存不足              | batch、序列长度、模型与缓存 |

调试四步：缩小输入；打印类型/形状；写最小复现；一次只改一个变量。

## 7. Git 的最小心智模型

Git 保存的是文件随时间变化的快照。三个区域：工作区（正在编辑）、暂存区（准备提交）、仓库历史（已经提交）。GitHub 是托管 Git 仓库的网站，不等于 Git。

```powershell
git init
git status
git add README.md
git commit -m "docs: add project overview"
git log --oneline
```

创建 `.gitignore`，至少忽略：

```gitignore
.venv/
__pycache__/
.pytest_cache/
.env
*.pyc
checkpoints/
outputs/
```

模型权重、数据集和 API Key 通常不应直接提交。Key 一旦进入 Git 历史，应立即吊销并更换，而不只是删除当前文件。

## 8. 可复现项目模板

```text
my_project/
├─ README.md
├─ requirements.txt
├─ .gitignore
├─ configs/
├─ data/              # 小样例；大数据只记录下载方法
├─ src/
│  └─ main.py
├─ tests/
│  └─ test_main.py
├─ outputs/           # 通常忽略
└─ notes/
   └─ experiment-001.md
```

README 至少回答：项目解决什么问题、如何安装、如何运行、输入输出示例、已知限制。

## 9. 测试不是“最后再补”

```python
# src/text_utils.py
def normalize_spaces(text: str) -> str:
    return " ".join(text.split())
```

```python
# tests/test_text_utils.py
from src.text_utils import normalize_spaces

def test_normalize_spaces():
    assert normalize_spaces("a   b") == "a b"

def test_empty_text():
    assert normalize_spaces("") == ""
```

运行：`python -m pytest -q`。神经网络里尤其要测试形状、有限值（无 NaN/Inf）、确定性和保存加载前后一致性。
