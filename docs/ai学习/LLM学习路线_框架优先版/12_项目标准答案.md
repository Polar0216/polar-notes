# 课后项目标准答案与结果核对

本文件用于完成项目后的对照检查，不替代独立实现。代码类项目允许存在不同正确写法；标准答案强调必须满足的语义、形状、测试和实验口径。

## 1. Project 1 标准答案

一份合格的全局图应包含：

```text
"我爱"
→ Tokenizer.encode
→ [id_我,id_爱]                                      [B,T]
→ Token Embedding + Position Embedding
→ 初始隐藏状态                                        [B,T,C]
→ Transformer Block × N
   ├─ LayerNorm → Causal Self-Attention → Residual    [B,T,C]
   └─ LayerNorm → MLP → Residual                      [B,T,C]
→ Final LayerNorm                                     [B,T,C]
→ LM Head                                             [B,T,V]
→ 取最后位置                                          [B,V]
→ Softmax                                             [B,V]
→ “猫”的概率
```

训练分支：

```text
logits [B,T,V] + targets [B,T]
→ cross entropy
→ scalar loss
→ zero_grad
→ backward
→ gradient clipping
→ optimizer.step
```

生成分支：

```text
last logits
→ temperature / top-k
→ softmax
→ sample one id
→ concatenate to input
→ repeat
```

关键解释：Attention 在位置之间交换信息；MLP 只在每个位置内部加工特征；Causal Mask 阻止未来答案泄漏。

## 3. Project 3 标准答案

下面是一份可直接运行的基础测试。保存到与 `mini_gpt_complete.py` 同一目录：

```python
import tempfile
from pathlib import Path

import torch

from mini_gpt_complete import (
    CharTokenizer,
    CausalSelfAttention,
    GPTConfig,
    MiniGPT,
)


def test_tokenizer_round_trip():
    text = "我爱猫。"
    tokenizer = CharTokenizer(text)
    assert tokenizer.decode(tokenizer.encode(text)) == text


def test_attention_and_model_shapes():
    torch.manual_seed(0)
    config = GPTConfig(
        vocab_size=11,
        block_size=8,
        n_layer=2,
        n_head=2,
        n_embd=8,
        dropout=0.0,
    )
    x = torch.randn(2, 5, 8)
    attention = CausalSelfAttention(config)
    assert attention(x).shape == x.shape

    model = MiniGPT(config)
    idx = torch.randint(0, 11, (2, 5))
    targets = torch.randint(0, 11, (2, 5))
    logits, loss = model(idx, targets)
    assert logits.shape == (2, 5, 11)
    assert loss is not None
    assert loss.ndim == 0
    assert torch.isfinite(loss)


def test_save_load_consistency():
    torch.manual_seed(0)
    config = GPTConfig(
        vocab_size=11,
        block_size=8,
        n_layer=1,
        n_head=2,
        n_embd=8,
        dropout=0.0,
    )
    idx = torch.randint(0, 11, (2, 5))
    model = MiniGPT(config).eval()
    with torch.no_grad():
        before, _ = model(idx)

    with tempfile.TemporaryDirectory() as directory:
        path = Path(directory) / "model.pt"
        torch.save(model.state_dict(), path)
        restored = MiniGPT(config)
        restored.load_state_dict(torch.load(path, map_location="cpu"))
        restored.eval()
        with torch.no_grad():
            after, _ = restored(idx)

    torch.testing.assert_close(before, after)


def test_zero_learning_rate_keeps_parameters():
    torch.manual_seed(0)
    config = GPTConfig(11, 8, 1, 2, 8, 0.0)
    model = MiniGPT(config)
    optimizer = torch.optim.SGD(model.parameters(), lr=0.0)
    idx = torch.randint(0, 11, (2, 5))
    targets = torch.randint(0, 11, (2, 5))
    before = [p.detach().clone() for p in model.parameters()]

    optimizer.zero_grad()
    _, loss = model(idx, targets)
    loss.backward()
    optimizer.step()

    for old, new in zip(before, model.parameters()):
        torch.testing.assert_close(old, new)


if __name__ == "__main__":
    test_tokenizer_round_trip()
    test_attention_and_model_shapes()
    test_save_load_consistency()
    test_zero_learning_rate_keeps_parameters()
    print("all tests passed")
```

未来注意力为零的测试需要在调试接口中取得 `weights`。判断标准是上三角所有元素接近零，而不是检查 Mask 原矩阵本身。

## 4. Project 4 标准答案

完整参考实现是 [code/mini_gpt_complete.py](code/mini_gpt_complete.py)。合格实现不必逐行相同，但必须通过以下数据流：

```text
text
→ tokenizer.encode
→ one-dimensional token stream
→ get_batch: x,y [B,T]
→ MiniGPT.forward
→ logits [B,T,V], loss scalar
→ backward + optimizer
→ validation
→ checkpoint
→ generate
→ tokenizer.decode
```

最低正确性标准：

- 所有形状断言通过。
- loss 有限且单批过拟合时明显下降。
- Causal Mask 不允许读取未来位置。
- `optimizer.step()` 后至少一个参数变化。
- `eval()` 下保存加载结果一致。
- 生成循环每轮只增加一个 token。

如果实现无法运行，按 Tokenizer、Batch、Embedding-only 模型、单头 Attention、多头 Attention、Block、完整模型、训练、生成的顺序回退定位。

## 5. Project 5 标准答案

该项目没有唯一数值答案，因为硬件、随机采样和训练过程会产生差异。标准实验报告应使用以下结构：

```markdown
# 实验标题

## 1. 实验问题
只比较 n_layer=1 与 n_layer=3 对结果的影响。

## 2. 控制变量
列出语料哈希、seed、B、T、C、H、训练步数、学习率和评估次数。

## 3. 原始结果
参数量、时间、train loss、validation loss、固定提示样例。

## 4. 观察
只描述表格和曲线直接支持的现象。

## 5. 解释
用模型容量、优化难度和过拟合解释，但标注为推测。

## 6. 局限
小语料、单随机种子、验证抽样和短训练不能支持普遍结论。

## 7. 下一步
增加随机种子或延长相同 token 预算后复验。
```

“较大模型一定更好”不是合格结论；必须说明当前实验条件。

## 6. Project 6 标准答案

预期趋势而非固定答案：

| 配置 | 常见趋势 |
|---|---|
| 贪心 | 完全确定，容易重复 |
| 低温度、小 Top-k | 较稳定，候选有限 |
| 温度 1 左右 | 保留模型原有随机性 |
| 高温度、大 Top-k | 差异增大，也更容易不通顺 |

必须多次运行随机采样，因为单个样本不能代表整个输出分布。若使用相同随机种子和完全确定的执行环境，多次结果可能相同，此时需要明确种子策略。

性能计时应区分首次运行预热和稳定运行，并固定生成 token 数。

## 7. Project 7 标准答案

以“私有课程资料问答”为例，合理的最小方案是 RAG，不需要先微调或构建自主 Agent：

```text
课程文档
→ 解析与分块
→ Embedding 与索引

用户问题
→ 查询检索
→ 重排
→ 取 Top-k 证据
→ 构造带来源 Prompt
→ LLM 生成
→ 检查引用与证据一致性
→ 返回答案和来源
```

必要控制：

- 只索引授权目录。
- 文档与用户权限关联。
- Prompt 中的文档内容视为不可信数据，不作为系统指令执行。
- 回答必须引用证据；证据不足时允许拒答。
- 分别评估检索召回和答案忠实度。
- 记录模型、索引和文档版本。

只有当系统需要多步选择检索、调用其他工具或迭代验证时，才在基线上增加受控 Agent。

## 8. 最终核对标准

标准答案的用途是定位差距：

```text
形状不同 → 检查接口与维度语义
步骤缺失 → 检查全局数据流
结果不同 → 先核对随机种子、配置和数据
代码不同但测试全过 → 可能同样正确
生成文本不同 → 随机采样下属于正常现象
```

完成对照后，把发现的问题写入自己的失败记录，不要用标准答案直接覆盖整个实现。
