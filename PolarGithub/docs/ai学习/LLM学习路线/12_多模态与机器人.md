# 模块 12（选修）：多模态、ROS 2 与机器人

## 目标

理解视觉语言模型（VLM）的数据流；在仿真中让 VLM 提取高层语义、Planner 生成受限目标、ROS 2/MoveIt 执行经过验证的动作。不要让自然语言模型直接输出电机控制量。

## 学习导航

先理解感知、规划和控制的职责边界；只在仿真和回放数据中验证，再完成验收与复盘，最后做文末 Project。真实硬件安全控制不能交给 LLM。

## 1. VLM 看见的是什么

常见架构：视觉编码器把图像变成视觉特征，经投影/适配器映射到语言模型维度，再与文本 token 一起处理。

```text
图像 → resize/normalize/patch → vision encoder → visual tokens
文本 → tokenizer → text tokens
visual + text → multimodal LLM → 文本/结构化输出
```

分辨率、裁剪和图像 token 数影响小物体、文字识别、延迟与显存。VLM 输出是概率性描述，不等于可靠的几何测量。

## 2. 多模态任务层级

- 描述/问答：图里有什么。
- OCR/文档：读文字和布局。
- Grounding：把文字实体对应到框/点。
- 空间关系：左右、遮挡、相对位置。
- 动作规划：根据场景产生高层步骤。

“看见杯子”到“机械臂抓住杯子”之间还缺相机标定、深度、位姿估计、坐标变换、运动规划、碰撞检测和控制反馈。

## 3. 机器人基础

### 坐标系与变换

机器人至少涉及世界、基座、末端、相机和物体坐标系。齐次变换矩阵表示旋转和平移：

$
T=\begin{bmatrix}R&t\\0&1\end{bmatrix}
$

若物体位置在相机坐标系，必须通过标定变换到机器人基座坐标系。坐标系方向、单位和时间戳错误会导致危险动作。

### 正逆运动学

正运动学：关节角→末端位姿。逆运动学：目标位姿→可能的关节角，可能无解或多解。MoveIt 等规划框架还会考虑关节限制与碰撞。

## 4. ROS 2 心智模型

- Node：单一职责进程/组件。
- Topic：发布订阅数据流，如相机图像、关节状态。
- Service：短请求响应。
- Action：可反馈、可取消的长任务，如移动到目标。
- Message：类型化数据。
- TF2：带时间的坐标变换树。
- Bag：录制与回放消息，便于复现实验。

LLM Planner 更适合调用受约束 Action/Service，如 `pick(object_id)`，而不是自由发布关节速度 Topic。

## 5. 推荐安全架构

```text
Camera / Sensors
→ Perception（检测、分割、深度、位姿、置信度）
→ Scene State（结构化、带时间戳）
→ VLM/LLM Planner（高层目标/步骤）
→ Symbolic Validator（对象、前置条件、权限）
→ MoveIt / Task Planner（轨迹与碰撞）
→ Safety Controller（速度/力/区域/急停）
→ Robot
→ Feedback 回到状态
```

LLM 输出必须通过 schema，例如 `{"action":"pick","object_id":"cup_3"}`，然后验证对象存在、置信度足够、区域允许、夹具可用。低置信度应请求重新观察或人工确认。

## 6. 仿真优先

顺序：纯软件单元测试→录制数据回放→Gazebo/Isaac Sim 等仿真→低速空载→软物体/安全区域→受监督真实任务。仿真不能证明现实绝对安全，但能低成本发现规划和接口错误。

真实机械臂必须有硬件急停、速度/力限制、碰撞检测、禁入区和现场监督。LLM 不能覆盖底层安全控制器。

## 7. 评估

- Perception：检测/grounding/OCR 的准确性与置信度校准。
- Planning：合法计划率、前置条件满足率。
- Motion：规划成功率、碰撞、轨迹长度、耗时。
- Task：端到端成功率和恢复率。
- Safety：越界动作数必须为 0；急停与超时测试通过。

端到端失败要分层归因，否则无法知道应改 VLM、标定、规划还是控制。

## 验收与复盘

- 能解释 VLM 不提供可靠几何控制的原因。
- 所有 LLM 动作结构化并经过确定性验证。
- 先在仿真与回放数据上评估。
- 坐标系、单位、时间戳和置信度都显式表达。
- 真实硬件安全独立于 LLM，具备物理急停和限制。

## 课后 Project

### Project 27A：图像问答

用小型 VLM 对自建 100 张图像集完成物体、属性、OCR 和空间关系问答。记录图像许可；评估准确率、拒答和幻觉；比较分辨率/提示方式的影响。

### Project 27B：桌面场景 Grounding

让模型输出受 schema 限制的对象列表和粗框/点；用传统检测或人工标注验证。把“语义名称”与“可操作实例 id”分离。

### Project 27C：仿真机械臂

在仿真中：用户说“把红色方块放进左侧盒子”→VLM/感知输出对象→Planner 生成 `pick/place`→验证器检查→MoveIt 规划→执行并根据结果更新。

测试：目标不存在、多个同名对象、被遮挡、不可达、规划失败、执行中物体移动、提示注入贴纸、通信超时。
